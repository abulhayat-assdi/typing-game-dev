# i18n Architecture (M3)

English default (`en`), Bangla (`bn`) fully supported. Typing GAME PROMPTS are
excluded — they belong to the content/game system (later milestone).

## Catalogs

`apps/web/messages/{en,bn}/*.json`, one flat string map per namespace:

| Namespace | Contents |
|---|---|
| `common` | app name, tagline, actions, generic states |
| `nav` | current + future module labels |
| `auth` | login/register labels, session messages |
| `errors` | boundary, 404, validation, network, storage messages |
| `a11y` | skip link, menus, dialogs, loading announcements |
| `home` | landing copy |

Flat keys keep `keyof` typing exact. Bangla files may omit keys; the loader
merges Bangla over English so missing keys fall back instead of blanking.

## API (`apps/web/lib/i18n.ts`, edge-safe)

- `resolveLocale(input)` / `isLocale(v)` — narrow unknown input.
- `splitLocalePrefix(path)` — `/bn/map` → `{ locale: 'bn', path: '/map' }`.
- `getMessages(locale)` — merged dictionary (server components).
- `createTranslator(primary, fallback)` + `getTranslator(locale, ns)` —
  typed `(key, vars?)` with `{var}` interpolation; unknown keys render
  `[key]` (never crash).
- `getNamespaceMaps()` — catalog-integrity tests assert Bangla introduces no
  unknown keys and ships no empty strings.

## Routing

`/{locale}/...` for UI (middleware folds missing/invalid prefixes to `en`);
API routes are locale-free. Error/not-found boundaries receive no params, so
they use default-locale copy by design (documented in the components).
